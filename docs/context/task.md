Тестове завдання: Проєктування Scraper-сервісу для збору файлів app-ads.txt

Контекст завдання:
У нашій екосистемі є велика база ідентифікаторів мобільних застосунків (десятки мільйонів Bundle ID) для App Store та Google Play. Для верифікації застосунків нам потрібен сервіс для збору й актуалізації даних.

Основний процес роботи (Core Flow):

● Discovery & Scraping маркетплейсів: За Bundle ID знайти сторінку застосунку
в App Store або Google Play, отримати інформацію про поточного видавця (Developer/Publisher) та URL його офіційного сайту.
● Fetching .txt файлів: Перейти на сайт видавця та завантажити цільовий файл.
Він завжди розміщується за типовою адресою:
https://[домен_видавця]/app-ads.txt.

Періодична актуалізація даних (Schedules)
● Щодня (Daily): повторні запити до сайтів видавців для перевірки змін у файлі
app-ads.txt.
● Щотижня (Weekly): повторна перевірка сторінки застосунку в App Store / Google Play (виявлення зміни власника, перейменування, видалення застосунку, зміни домену розробника тощо).

Очікуваний результат: Короткий документ у довільному форматі (до 2 сторінок) з архітектурним рішенням та поетапним планом імплементації. Нам не потрібен вичерпний System Design, ми хочемо зрозуміти ваш підхід до проєктування, хід думок і логіку прийняття технічних рішень.
